How a notification travels

a row in notifications→ tg_enqueue_push→ notification_queue→ cron, every minute→ phone push + bell
  • The pipe is already built and running. What is missing is the part that decides when to write the row. That is what this page plans.
  • Priority 0 sends now. Priority 1 waits for quiet hours. Priority -1 never pushes — bell only.
  • The words can be changed in the database (notification_templates) with no deploy. One row per key. Placeholders: {trip} {item} {actor} {qty} {days}. New ones we would need: {amount} {count} {date}.
  • A daily job already exists — scan-trip-reminders, 06:07 UTC. Most of this plan is new rules inside that same job.
  • Documents and money are the same kind of row (organized_trip_requirements) with a due date. One engine can chase both.
